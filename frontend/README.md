# favourite

Node 22 и Yarn Classic 1.22.22. Источник версий — `yarn.lock`. Сборка проверяет TypeScript, затем создаёт Vite/PWA assets. `package-lock.json` не используется.

`workbox-build` генерирует service worker при сборке. `workbox-window` регистрирует и обновляет его в браузере через `virtual:pwa-register`. Оба используются существующим `vite-plugin-pwa` и закреплены явно как его peer-зависимости. Настройки кеша API этим не добавляются.

## Идеи для фронтенда (бэклог)

Идеи ниже — ориентиры для UX и фич; реализовать можно выборочно.

### Доверие и доступность

- **Экспорт данных** (например JSON/CSV коллекции) — переносимость и ощущение контроля над своими данными.
- **Доступность**: фокус в модалках, контраст, уважение к `prefers-reduced-motion`.

### Технологии и удобство доступа

#### PWA (установка на домашний экран)

- **`manifest.webmanifest`** — имя приложения, иконки 192 / 512 (в т.ч. maskable), `display: standalone`, `start_url`,
  тема.
- **Service Worker (Workbox)** — предкеш статических чанков после `vite build`; для SPA включён *
  *`navigateFallback: /index.html`**, чтобы при обновлении страницы по прямой ссылке не было 404.
- **Регистрация SW** — `PwaStatus.vue` использует `useRegisterSW` и предлагает обновление новой сборки. Перезагрузка выполняется после подтверждения, чтобы не терять несохранённые формы (`registerType: 'prompt'`). Проверка обновлений повторяется при возврате сети и фокусе окна.
- **Админские чанки** не входят в общий precache. После первого открытия они кешируются отдельно по хешу имени. API и пользовательские данные service worker не кеширует. Для загрузки данных и сохранения требуется сеть.

Иконки лежат в **`public/pwa-192.png`** и **`public/pwa-512.png`** (сейчас однотонные заглушки под primary `#1677ff`).
Перегенерация:

```
yarn pwa:icons
```

(скрипт `scripts/generate-pwa-icons.mjs`, dev-зависимость `pngjs`).

**Что это даёт пользователю:** ярлык на рабочий стол / экран, запуск без адресной строки (standalone), быстрый повторный
вход на уже закешированную оболочку приложения.

**Ограничения:** данные API и личная коллекция в офлайне **не гарантируются** — для полноценного офлайн-режима списка
нужны отдельные стратегии кеширования запросов и синхронизация (в бэклоге идей выше это «при желании офлайн-чтение»).

**Как проверить локально**

1. Сборка и превью продакшена (SW в dev по умолчанию выключен: `devOptions.enabled: false`):

   ```
   yarn build && yarn preview
   ```

   Открыть URL из консоли (обычно `http://localhost:4173`).

2. **Chrome / Edge:** DevTools → вкладка **Application** → **Manifest** (проверить имя, иконки), **Service Workers** (
   статус activated). В адресной строке может появиться иконка «Установить» / меню «Установить приложение…».

3. **Safari (iOS):** через превью по локальной сети установка ограничена; для реальной проверки «Добавить на экран
   домой» нужен **HTTPS** и доступ с телефона (или ngrok и т.п.).

4. Установка и push-токены на продакшене требуют **`https://`** (исключение — `localhost`). Убедись, что сервер отдаёт
   корректные заголовки для JS/CSS и не ломает путь к `/sw.js` и `/manifest.webmanifest`.

**Замечание:** в `yarn dev` PWA обычно не используют; для отладки SW можно временно выставить
`devOptions.enabled: true` в `vite.config.ts`.

## Продукт и контент (статус)

Финальная сверка по четырём опорам из раздела «Продукт и контент» выше.

1. **Сериалы по сезонам и сериям — готово.** Бэкенд: нормализация прогресса и статуса в `UserMovieService`, поля
   сезона/серии.
   UI: `MovieDetail.vue` (сегмент статуса, ±сезон/серия, пресеты). Искать коллизии статуса при максимальном прогрессе не
   нужно — явный выбор пользователя сохраняется.

2. **Свои списки и метки — готово (MVP).** API `user-list`, Pinia `userListsStore`. UI: страница **«Мои списки»**
   (`MyListsPage.vue`: фильтры, метки, URL, удаление списка и тайтла из списка), модалка «В список» в `MovieDetail.vue`.
   **Не входит в MVP:** шаринг списка друзьям как отдельная фича (остаётся в идеях выше).

3. **Быстрый ввод — готово.** На странице коллекции (`MovieList.vue`) плавающая кнопка и панель с автодополнением по
   запросу
   к каталогу (`/movies/search`). **Уточнение:** удобнее всего вводить **название**; распознавание вставленной **только
   **
   URL-карточки `/detail/:id` в поле быстрого вода отдельно не разбирается (при желании — отдельная маленькая задача).

4. **Аналитика пользователя — готово (личная сводка).** Эндпоинт аналитики по коллекции, блок «Персональная аналитика»
   на
   `ProfilePage.vue` (тренд 7/30, топ жанров, продолжить смотреть, быстрые переходы в коллекцию с фильтрами).
   **Не сделано:** пересечения коллекции с друзьями — это социальная аналитика и другой объём данных/API (остаётся в
   бэклоге идей).

## Бэкенд (сделано в репозитории)

Подумать где использовать и с чем SSE (server side events).

- **Swagger:** в `include` добавлены **Friendship**, **Message**, **Badge**; защищённые ручки помечены декоратором \* \*
  `AuthProtected()`** (`ApiBearerAuth` + JWT). У **Users** и **Actors\*\* добавлены `@ApiTags` / `@ApiOperation` где не
  хватало.
- **Роли:** `USER` и `ADMIN`. Общие фильмы/актёров редактирует администратор. Пользователь может создавать записи и редактировать свои. Личная коллекция доступна только владельцу.
- **JWT `@me`:** в `req.user` не попадает `password`.
- **Rate limit:** `ThrottlerModule` + лимиты на `login` / `register` / `refresh`; `logout` и `GET auth/@me` без лимита (
  `SkipThrottle`).
- **CORS** с `credentials` настраивается в `backend/src/main.ts` (`CORS_ORIGINS` / `FRONTEND_ORIGIN`).

### Что сделать локально после `git pull`

1. В каждом приложении выполнить `yarn install --frozen-lockfile`. В `backend` выполнить `yarn prisma generate` и `yarn prisma migrate deploy`. Не использовать reset при расхождении истории.
2. **ADMIN** нужен для администрирования пользователей и общего каталога. Обычная регистрация всегда создаёт `USER`.
3. В проде проверить **cookie** refresh (`COOKIE_DOMAIN`, `sameSite`, `secure`) под домен и HTTPS.
