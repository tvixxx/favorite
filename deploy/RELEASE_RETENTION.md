# Ротация релизов FavouriteApp

Политика: сохранять 3 последние завершённые точки возврата.
Дополнительно всегда сохранять точку из ci-last-success.json и незавершённые
точки для ручного разбора. Обычные дампы и внешние S3-копии имеют прежнюю
GFS-ротацию и этим инструментом не изменяются.

## Что защищено

- Образы всех существующих контейнеров, включая остановленные.
- Три образа последнего успешного CI-deploy, в том числе migrate.
- Образы сохраняемых точек возврата.
- Неизвестные каталоги, образы других проектов и образы с чужими метками.
- PostgreSQL, AWS CLI, Certbot, тома, контейнеры и кеш сборки не очищаются.

Удаляются только завершённые устаревшие каталоги releases с проверенной
структурой и неиспользуемые образы приложения. Для образа нужны метаданные
источника tvixxx/favorite либо принадлежность проверенной точке возврата.
Все ссылки образа должны относиться к разрешённым именам приложения.
Старый локальный migrate без подтверждённого источника может остаться,
его удаление требует отдельного рассмотрения.

Без --apply выводится только JSON-план. Не применять первый план до просмотра
оператором. Не делать общий docker system prune / image prune и не добавлять
--force. Для image rm используется --no-prune, чтобы не удалять нетегированных
родителей неявно. Оценивать освобождённое место по df после выполнения.
Размеры Docker Images/Build Cache нельзя складывать как независимые данные.

При некорректной структуре, ссылках, неизвестных файлах в точке, нездоровом API,
расхождении текущих контейнеров и последнего успеха очистка завершается ошибкой
до удалений. При поздней ошибке часть старых образов уже может быть удалена.
Архивы удаляются после обработки образов. Сохраняемые точки и текущие образы
из плана удаления исключены. Удалённые старые объекты автоматически не возвращаются.

## Установка по этапам

1. Передать rotate-releases.cjs и два systemd-файла в отдельный каталог deploy.
   Сверить SHA-256 с проверенной локальной версией.
2. Создать новый /usr/local/lib/favkino-maintenance с правами 0700 root:root,
   установить rotate-releases.cjs с 0600 root:root. Не перезаписывать существующую
   установку без проверки и резервной копии.
3. Проверить node --check и выполнить предпросмотр под общим lock:

```bash
sudo flock --close -w 900 /run/lock/favkino-deploy-backup.lock /usr/bin/env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin /usr/bin/node /usr/local/lib/favkino-maintenance/rotate-releases.cjs
```

4. Оператор проверяет keepPoints/removePoints/removeImages и разрешает
   первое применение. Для него к той же команде добавляется --apply.
   Во время установки не запускать параллельно ручной deploy/rollback.
5. Проверить df, docker ps и HTTPS health после первого применения.
6. Перед включением расписания опубликовать и доставить изменения deploy.sh
   и rollback.sh, добавляющие общий lock. Не делать push до освобождения
   достаточного места, CI требует минимум 8 ГиБ перед pull.
7. Установить favkino-release-cleanup.service и .timer в /etc/systemd/system
   с 0644 root:root. Проверить systemd-analyze verify и календарь через
   systemd-analyze calendar '*-*-* *:10/15:00'. Выполнить daemon-reload.
8. После успешной проверки и согласования включить таймер:
   systemctl enable --now favkino-release-cleanup.timer.
   Проверить is-enabled, is-active и list-timers. Подтвердить реальный запуск
   по journalctl, ручной start не доказывает срабатывание расписания.

Таймер проверяет ротацию раз в 15 минут с небольшим случайным сдвигом.
Сервис использует /run/lock/favkino-deploy-backup.lock, как CI и бэкапы.
Root-owned копия скрипта не обновляется автоматически при git pull.
При изменении источника установленную копию обновлять отдельно с проверкой хеша.

## Проверки

node --test deploy/rotate-releases.spec.cjs

Тесты используют настоящие временные каталоги и подменённые ответы Docker.
Они не подтверждают совместимость Go templates с Docker на VPS или выполнение
systemd. Это отдельно проверяется реальным предпросмотром и установкой.
Ротация не ограничивает размер одной точки или БД, оповещения о сбоях
настраиваются отдельно.
