# Развёртывание Favorite на Timeweb Cloud

Схема: **один домен на всё**. nginx раздаёт собранный фронтенд, проксирует
`/api` в NestJS и `/socket.io` для чата. Так refresh-кука остаётся first-party,
CORS не нужен, а `sameSite: none; secure` из кода работает как задумано.

```
браузер ──► nginx (80/443) ──┬──► /            статика Vue (в образе web)
                             ├──► /api/        backend:3005  (префикс срезается)
                             └──► /socket.io/  backend:3005  (WebSocket upgrade)
                                      └──► postgres:5432 (наружу не публикуется)
```

## Что заказать в Timeweb

- **Cloud Server**, Ubuntu 24.04, 2 vCPU / 2 ГБ RAM / 40 ГБ — с запасом на сборку образов.
- **Публичный IP** и A-запись домена на него (в разделе DNS панели).
- Порты 80 и 443 открыть в firewall панели (плюс `ufw` настроит сам скрипт).

Managed Postgres в Timeweb брать не обязательно: в этой схеме база живёт рядом
в контейнере, а бэкапы делают наши скрипты. Если возьмёте managed — уберите
сервис `postgres` из compose и подставьте его `DATABASE_URL`, но **сверьте
мажорную версию**: compose закреплён на `postgres:18-alpine` под локальные 18.x,
и дамп `pg_dump -Fc` с 18 на 16 не восстановится.

## Первый деплой — четыре команды

```bash
# 1. на сервере
apt update && apt install -y git
git clone <ваш-репозиторий> /srv/favorite && cd /srv/favorite/deploy

# 2. заполнить секреты
cp .env.example .env && nano .env
#    DOMAIN, LETSENCRYPT_EMAIL
#    POSTGRES_PASSWORD=$(openssl rand -base64 32)
#    JWT_SECRET=$(openssl rand -base64 48)
#    остальное можно оставить как в примере

# 3. поднять по HTTP (поставит docker/node, firewall, соберёт образы, накатит миграции)
chmod +x bootstrap.sh deploy.sh && ./bootstrap.sh

# 4. включить HTTPS и расписание бэкапов
./bootstrap.sh certs
./bootstrap.sh cron
```

После третьего шага приложение уже открывается по `http://ваш-домен`.
Четвёртый выдаёт сертификат Let's Encrypt, переключает nginx на HTTPS и ставит
в cron почасовой бэкап + недельное продление сертификата.

⚠️ Строки из `.env.example` **не удаляйте**, даже если значение пустое. Бэкенд
читает `NODE_ENV`, `DATABASE_URL`, `JWT_SECRET`, `JWT_ACCESS_TOKEN_TTL`,
`JWT_REFRESH_TOKEN_TTL` и `COOKIE_DOMAIN` через `getOrThrow` — без любой из них
контейнер не поднимется вообще. Пустой `COOKIE_DOMAIN` при этом допустим и
означает host-only куку, что для одного домена и нужно.

## Обновления потом

```bash
cd /srv/favorite/deploy && ./deploy.sh
```

Скрипт делает всё в правильном порядке: **слепок базы → сборка → перезапуск →
`prisma migrate deploy` → проверка живости API**. Если миграция упадёт,
откат — из слепка, снятого этим же запуском.

## Проверка после деплоя

| Что | Как |
|---|---|
| Фронтенд | открыть `https://домен`, увидеть экран входа |
| API | `curl -si https://домен/api/movies \| head -1` |
| Куки | войти, обновить страницу — сессия должна сохраниться |
| Чат | открыть «Общение» в двух браузерах, отправить сообщение (это проверка WebSocket) |
| PWA | DevTools → Application → Service Workers: `sw.js` зарегистрирован |
| Бэкап | `node ../backend/scripts/backup/db-verify.cjs` |

Скрипты бэкапа запускаются **с хоста** (внутри контейнера нет `docker`), но
внешних пакетов не требуют — только встроенные модули Node, поэтому `npm ci`
на сервере делать не нужно.

## Что нужно поправить в коде до продакшена

Проверено по текущему состоянию репозитория:

1. **Порт 3005 зашит** в `backend/src/main.ts` (`app.listen(3005)`). Внутри
   docker-сети это не мешает, но лучше вынести в `PORT` с дефолтом.
2. **Нет health-эндпоинта** (`/health` и `/healthz` дают 404). `deploy.sh` проверяет
   живость через `/api/movies` — он публичный и отдаёт 200 без токена. Отдельный
   `GET /health` был бы честнее и пригодился бы для мониторинга.
3. **Socket.IO gateway с `cors: { origin: '*' }`** (`message.gateway.ts`).
   За одним доменом это безопасно, но лучше сузить до своего origin.
4. **Демо-данные.** `backend/scripts/seed-demo-movies.cjs` на прод не запускать;
   если запустили — `--remove`.
5. **Расхождение схемы на `movies`.** Локально мы не используем `migrate dev`.
   На сервере — только `migrate deploy`, и всегда после слепка базы.

### Чистая база на сервере ≠ локальная (проверено)

`bootstrap.sh` накатывает миграции на пустую базу, и она получается **не такой**,
как локальная — та правилась руками. Прогнал историю миграций на отдельной базе
и сравнил структуру `movies`:

| Колонка | Локально | На сервере (из миграций) |
|---|---|---|
| `country_codes` | `text[]`, nullable | `varchar(2)[]`, NOT NULL |
| `genres` | nullable, без значения по умолчанию | NOT NULL, по умолчанию `{}` |
| `title_normalized` | по умолчанию `''` | без значения по умолчанию |

Приложение с такой базой работает: проверил создание и чтение фильма с жанрами и
странами через настоящий клиент Prisma — всё проходит, `title_normalized`
подставляется на стороне клиента. Ограничение `varchar(2)` безвредно: DTO
пропускает только коды из белого списка ISO alpha-2 (`@IsIn`).

Серверный вариант при этом **строже** и ближе к `schema.prisma` — там, где локально
`genres` бывает `NULL` (известная проблема данных), на сервере это невозможно.

## Если что-то не работает

```bash
docker compose ps                      # кто упал
docker compose logs --tail=100 backend # логи бэкенда
docker compose logs --tail=50 web      # логи nginx
docker compose exec postgres psql -U $POSTGRES_USER -d $POSTGRES_DB -c '\dt'
```

Частые причины:

- **502 на `/api`** — бэкенд не поднялся, смотрите его логи (обычно `DATABASE_URL`).
- **Кука не сохраняется** — сайт открыт по HTTP. Кука выставляется с `Secure`,
  по HTTP браузер её выбрасывает. Нужен шаг `./bootstrap.sh certs`.
- **Чат не подключается** — проверьте, что запрос идёт на `wss://домен/socket.io/`
  и что в nginx активен блок `location /socket.io/` с заголовками `Upgrade`.
- **Сертификат не выдаётся** — A-запись ещё не разошлась. Проверьте `dig +short домен`.

## Бэкапы

Настройка, ротация и восстановление описаны в
[`backend/scripts/backup/README.md`](../backend/scripts/backup/README.md).
Главное: заполнить `S3_URI` и `GPG_RECIPIENT` в `deploy/.env` — иначе копия
лежит на том же диске, что база, и не спасёт от потери сервера.
