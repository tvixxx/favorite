# Восстановление пароля

SMTP — подключение backend к почтовому сервису, который отправляет письма со ссылкой восстановления. Отдельное приложение или почтовый сервер на VPS разворачивать не требуется. Nodemailer работает внутри backend. Тариф и лимиты отправки зависят от выбранного почтового сервиса.

## Подключение

По умолчанию `PASSWORD_RECOVERY_ENABLED=false`. Backend не создаёт SMTP transport, публичный `GET /auth/password/capabilities` возвращает только `{ "passwordRecovery": false }` с `Cache-Control: no-store`. Frontend скрывает «Забыли пароль?» и не открывает окно через `recover=1`. Прямой переход на `/reset-password` показывает недоступность, прямые корректные `POST /auth/password/request` и `/reset` отвечают 503 без поиска аккаунта или расходования токена. Старые ссылки временно не работают при отключении, сами записи в БД не удаляются и продолжают истекать по обычному сроку.

1. Выберите сервис с SMTP и подтвердите адрес отправителя. Если он требует домен, настройте выданные им DNS-записи SPF/DKIM, затем DMARC по инструкции сервиса.
2. В локальной конфигурации backend или закрытом env-файле Compose задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_FROM`, `SMTP_USER`, `SMTP_PASS`. Логин и пароль задаются вместе. Не добавляйте их в Git и не присылайте в чат.
3. Обычно порт 587 использует `SMTP_SECURE=false` и STARTTLS, порт 465 — `SMTP_SECURE=true`. В production шифрование обязательно. Compose передаёт эти параметры backend при обычном деплое.
4. `FRONTEND_ORIGIN` должен быть корнем адреса приложения, например `https://favorite.example`, без пути, query и fragment. В Compose он уже берётся из `DOMAIN`. Production требует HTTPS.
5. Проверьте применённые миграции обычным согласованным способом. Миграция recovery уже входит в текущие20миграций и ранее применена локально. Новый toggle миграции не требует. Production deploy применяет отсутствующие миграции после резервного копирования по существующему сценарию.
6. В закрытом окружении backend установите `PASSWORD_RECOVERY_ENABLED=true`. Допустимы только строки `true` и `false`. Включение без `SMTP_HOST` и ошибочная SMTP/TLS-конфигурация останавливают запуск. Выключенный режим не требует SMTP-настроек.
7. Перезапустите backend с новым окружением. В Compose одного `restart` недостаточно для изменения environment, требуется пересоздание backend-контейнера, например штатный согласованный `docker compose up -d --no-deps --force-recreate backend`. Frontend пересобирать не нужно. При новом открытии страницы входа или сброса доступность запрашивается заново. Уже открытая страница сама не получает push-обновление, её нужно обновить.
8. Запросите восстановление для своего тестового аккаунта и проверьте входящее письмо, «Спам», адрес ссылки, смену пароля и вход новым паролем. Это необходимо повторить с реальным провайдером, локальный SMTP capture не подтверждает доставку в почтовые ящики.

Для отключения верните `PASSWORD_RECOVERY_ENABLED=false` и перезапустите backend с новым окружением. Backend немедленно после перезапуска отклоняет действия даже из старого frontend, который ещё показывает кнопку. Ошибка загрузки capabilities на frontend не включает функцию, на странице reset доступен повтор проверки. Boolean отражает включение и проверку конфигурации при запуске, а не подтверждённую доставку. Неверные учётные данные или отказ внешнего SMTP фиксируются общей записью backend без email, ссылки и пароля. Публичный ответ не раскрывает существование аккаунта и не гарантирует доставку письма.

## Ограничения и проверка

- Ссылка действует 15 минут и используется один раз. В БД хранится только SHA-256 хеш случайного токена. Токен в fragment URL не отправляется серверу при открытии страницы.
- Повторное письмо одному аккаунту отправляется не чаще раза в минуту. Новая ссылка заменяет старую. Есть ограничения запросов по IP и числа ожидающих отправок.
- Смена пароля отзывает прежние сессии. Заблокированный аккаунт восстановить нельзя.
- Остановка backend может прервать ещё не доставленное письмо. Пользователь может повторить запрос через минуту. Отдельная долговечная очередь не используется.
- Локальная интеграционная проверка с одноразовым PostgreSQL-стендом: `yarn --cwd backend test:postgres password-recovery.postgres-spec.ts`. Скрипт использует только QA-порт 55441 и собственную временную БД, SMTP capture запускается на loopback автоматически.
