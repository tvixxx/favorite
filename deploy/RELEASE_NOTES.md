# Новости релизов и системные объявления

Перед релизом с заметными для пользователя изменениями обновите `backend/release-notes/current.json`.

- `id` — новый постоянный идентификатор, например `2026-11-watch-diary`. Один id публикуется только один раз. Повторный деплой не создаёт дубль и не меняет уже опубликованный текст.
- `title` — короткий заголовок до 120 символов.
- `body` — обычный текст до 5000 символов. Кратко опишите пользу и исправления. Переносы строк сохраняются.
- `actions` — необязательный массив, максимум 2 кнопки. У кнопки `label` до 40 символов и `path`, поддерживаемый маршрут внутри SPA. Например `/notifications`, `/library/diary`, `/library/catalog`, `/friends?tab=requests`. Внешние URL, произвольные параметры, административные и служебные маршруты не принимаются.

Исправления без новой новости: оставьте прежний файл с прежним id. Чтобы полностью пропустить публикацию, содержимым файла может быть JSON `null`.

CI и ручной deploy публикуют запись только после запуска backend/web, проверки nginx и `check_application`. Перед миграцией остаются существующие локальный и проверенный внешний бэкапы. Ошибка публикации видна как ошибка deployment, приложение автоматически не откатывается. Дальнейшие действия выбираются после чтения журнала.

Системная новость хранится один раз, прочтение индивидуально. Непрочитанная публикация доступна также после входа с другого устройства или регистрации нового пользователя. Архивация скрывает её из пользовательской истории, запись остаётся в админке.

Произвольные объявления: Админка → Объявления → Создать → Сохранить черновик → Предпросмотр и публикация → Опубликовать для всех. До последнего шага объявление видно только администраторам. Опубликованный текст неизменяем, исправление выпускается отдельным объявлением. Доступна архивация с подтверждением.

Кнопка проверки обновления использует существующее подтверждение PWA. Сайт не перезагружается автоматически. Проверка наличия новой версии и запись о релизе в истории — независимые состояния.

После слияния текущая настройка DEPLOY_ENABLED запускает production автоматически. Этот файл описывает процесс, не является разрешением выполнить commit, push или deploy.
