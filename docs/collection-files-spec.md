# Экспорт коллекции и импорт прогресса/дат

Согласовано в чате 16 октября 2026. Порядок: спецификация, black-box тесты, код. Без commit/push. Рабочие пользовательские записи для проверок не изменять. Миграция БД не требуется.

## Данные и совместимость

- JSON v2: `{version:2,exportedAt:<UTC ISO>,movies:[...]}`. CSV v2: колонка `formatVersion` со значением 2 и те же поля одной записи.
- Запись: title, year, isSerial, contentKind, watchStatus, isFavorite, seeLater, personalRate, currentSeason, currentEpisode, addedAt, lastWatchedAt, startedAt, completedAt, droppedAt.
- В v2 все поля записи обязательны. year/contentKind/оценка/прогресс и все даты кроме addedAt допускают null. Исторический 0 и null у оценки сохраняются как разные исходные значения, но оба по-прежнему отображаются как «без оценки». NULL категории старых карточек не заменяется GENERAL.
- Прогресс сохраняется точно, даже если сведения о числе серий в каталоге изменились. Положительный прогресс у несериального тайтла отклоняется. Числа прогресса: целые 0–2147483647. Никакого автоматического заполнения до конца или установки текущей даты для v2.
- Даты принимаются только как действительные ISO timestamps с явной зоной, записываются как тот же момент времени. Null сохраняется. Служебные createdAt/updatedAt, ID пользователя, email, отзывы, списки, изображения и учётные данные в CSV/JSON не входят.
- JSON v1 и старый CSV продолжают работать с прежними defaults и нормализацией статусов/дат/прогресса. Для v1 сохраняются пределы 200 строк/32 КиБ. Для v2 пределы 1000 строк/2 МиБ. Превышение даёт явную ошибку, никакого усечения данных.
- CSV UTF-8 с BOM, запятая, CRLF, кавычки и удвоение внутренних кавычек. В CSV v2 title всегда начинается с технического апострофа для защиты от формул. Импорт v2 удаляет ровно один апостроф. Начальный настоящий апостроф сохраняется. В JSON исходный title не меняется.
- Неизвестные поля, повреждённый CSV, неверные даты, типы, версии, значения и prototype keys отклоняются до записи.

## Импорт

- Preview не пишет данные. Совпадение ищется по названию, году, виду и формату. Неоднозначное совпадение по-прежнему требует выбора карточки.
- Существующие записи коллекции пропускаются целиком, включая старые даты/прогресс/оценки. Повторный импорт не меняет их.
- Подтверждение привязано к содержимому, выбранным совпадениям, пользователю, authVersion и состоянию каталога. Сохраняется транзакция и прежние блокировки. Ошибка любой строки откатывает всю новую партию.
- V2 сохраняется через отдельный путь создания связи без нормализации обычного ручного добавления. Не менять основную логику фильмов/сериалов ради импорта.

## Экспорт и UI

- Только владелец своей коллекции. GET /users/:userId/movies/export, scope=all|filtered|completed, format=json|csv|pdf. По умолчанию all/json.
- all игнорирует фильтры, поиск и пагинацию. filtered использует тот же поиск и все фильтры, что коллекция, но все совпадения, а не загруженную страницу. completed выбирает просмотренные тайтлы.
- Выборка ограничена максимумом + 1 для явной проверки переполнения, стабильная сортировка addedAt desc/id asc. Один запрос получает согласованный снимок строк. Сохранять файлы на сервере не нужно. Ответы private/no-store, attachment для CSV/JSON.
- «Файлы» рядом с «Добавить» содержит «Импорт коллекции» и «Скачать коллекцию». Настоящие существующие Dropdown/Menu/BaseModal, никаких отдельных окон другого стиля.
- В окне форматы JSON/CSV/PDF, вся коллекция или текущие фильтры. Для PDF дополнительно «Только просмотренное», это начальный выбор PDF. Изменение пользователем выборки явно сохраняется при действиях в текущем окне.
- JSON/CSV: «Скачать JSON/CSV». PDF: «Скачать PDF» и «Открыть для печати», опция «С постерами» включена по умолчанию.
- Empty/loading/error/retry, блокировка повторного запуска, отмена запроса и запрет позднего скачивания при закрытии/смене аккаунта. Blob URL отзывается после использования. Ошибку видно без открытия консоли.

## PDF

- Пользователь прямо разрешил оба способа и постеры, без отзывов. PDF формируется в браузере, на сервере не хранится. Скачанный файл самодостаточен и подходит для отправки другому человеку.
- Отдельный report payload для format=pdf отдаёт только название/год/вид/формат/статус/личную оценку/дату завершения и URL постера. Не импортируется как JSON v2.
- A4, заголовок и количество тайтлов, компактные строки с постером, названием, годом, типом, оценкой и датой завершения. При выгрузке всей коллекции показывать статус, чтобы непросмотренное не выдавалось за просмотренное. Даты отчёта используют сохранённую IANA-зону профиля.
- Постеры уменьшаются до миниатюр JPEG, встраиваются в PDF. Ограниченная параллельная загрузка, таймаут, no-referrer, без авторизационных заголовков сторонним URL. Недоступный/CORS-запрещённый постер заменяется заглушкой и сообщением о пропусках. Backend не скачивает внешние URL.
- PDF-библиотека загружается динамически только по действию PDF. Перед установкой пользователь потребовал Context7, актуальную проверку уязвимостей/Snyk, совместимость с Vue и измерение размера production chunk. Выбор pdfmake@0.3.11 разрешён условно после этих проверок. Если размер неоправдан, пересмотреть выбор.

## Доказательства приёмки

- Export JSON/CSV → preview → import в отдельную коллекцию → сравнение всех полей, включая null/0, UTC и offset dates, старую NULL категорию, прогресс за пределами обновлённого каталога.
- V1 happy-path и негативные проверки остаются. Повреждённые v2 не пишут, повтор/существующие не меняются, отказ на чужой коллекции.
- Экспорт больше страницы, фильтры/поиск/категории совпадают с коллекцией. Никаких чужих полей, скрытых отзывов, email и секретов.
- CSV кавычки/запятые/формулы/настоящий начальный апостроф восстанавливаются точно. Нет усечения по лимиту.
- Реальный PDF с кириллицей и постером открывается, проверены несколько страниц, отсутствие отзывов/секретов, fallback картинки, скачивание и печать. Размер lazy chunk измерен, initial route не включает PDF-код.
- Реальные Vue templates, desktop/mobile, все темы и focus/Escape. Основную БД не использовать для тестовых импортов.

## Зависимость PDF

- Пользователь разрешил точную версию pdfmake 0.3.11. Совместима с текущим Vue 3.5 как обычный динамически импортируемый browser-модуль. Существующие шрифты сайта используются вместо большого Roboto VFS.
- Изолированный `npm audit --omit=dev` для реально разрешённого production-дерева pdfmake 0.3.11 → 27 пакетов, 0 известных уязвимостей. Это не гарантирует отсутствие неизвестных проблем.
- [Snyk pdfmake](https://security.snyk.io/package/npm/pdfmake) и [maintainer releases](https://github.com/bpampuch/pdfmake/releases) сверены. Исторический SSRF для старых версий сопоставлен с [GitHub advisory](https://github.com/advisories/GHSA-wp52-r2fp-4vmr). Серверное скачивание URL в приложении не используется.
- Browser API getBlob/print и custom fonts сверены через Context7 и [официальные методы pdfmake 0.3](https://pdfmake.github.io/docs/0.3/getting-started/client-side/methods/).

## Поправка после пользовательской проверки

- Пользователь подтвердил корректную работу экспорта и показал нативный предпросмотр печати PDF. На мобильной странице выявил сжатую навигацию рядом с кнопкой «Файлы». Предыдущая агентская проверка окна экспорта не охватывала это пересечение панели страницы.

- Браузерная проверка текущей страницы: 320, 390, 768, 960, 1024, 1440 px. Измерены реальные viewport и прямоугольники навигации/действий. Наложений и горизонтального переполнения страницы нет. Мобильный вид и открытое меню визуально проверены в светлой и тёмной теме. После закрытия импорта фокус возвращается на «Файлы коллекции».
- `cd frontend && yarn test:unit run src/styles/media.spec.ts src/components/CollectionImport/CollectionImportModal.spec.ts --config /private/tmp/favourite-main-vitest.config.mts --maxWorkers=2` → 10 тестов прошли. `yarn lint` и `yarn type-check` → прошли.
- [Рабочий пример JSON v2](examples/collection-import-v2.json) содержит две отсутствующие в текущей коллекции карточки из существующего каталога.
