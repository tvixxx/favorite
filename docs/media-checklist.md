# Ручная проверка изображений и подготовки VPS

Для проверок создавайте отдельные тестовые записи. Включённый S3 требует собственной конфигурации, локальные файлы работают без S3. Перед проверкой примените миграции по инструкции запуска.

1. **Создание фильма.** Медиатека → Добавить. Выберите «С устройства», JPEG/PNG/WebP, заполните название, описание, страны и жанры. Пока загрузка идёт, сохранение недоступно. После обработки видны размеры. Сохраните, обновите страницу, откройте карточку. Постер должен сохраниться.
2. **Создание сериала.** Повторите с типом «Сериал», сезонами и эпизодами. Поля остаются на всю ширину. Сохранение постера не меняет статус и личную оценку.
3. **URL.** Выберите «По ссылке», вставьте доступный HTTPS-адрес и нажмите «Показать». Должен появиться предпросмотр. `javascript:` и ссылка со встроенным логином отклоняются. Неработающая ссылка показывает понятный fallback.
4. **Замена постера.** Откройте свой фильм → «Изменить постер». Выберите другую картинку, сохраните, обновите страницу. На телефоне кнопка находится в мобильной строке действий. На десктопе это компактный карандаш в нижнем правом углу самого постера.
5. **Отмена.** В редактировании уберите картинку, затем нажмите «Отмена». Сохранённый постер должен остаться. Выберите другой файл во время первой загрузки. Поздний ответ первого не должен заменить второй.
6. **Ошибка замены.** Отключите сеть после выбора нового файла. После ошибки предыдущая сохранённая картинка должна оставаться доступной. Включите сеть и повторите.
7. **Аватар.** Профиль → Настройки → «С устройства». Сохраните, обновите страницу. Фото видно в профиле и меню аккаунта. Уберите фото и сохраните: вернутся инициалы. Имя не должно измениться само.
8. **Фото актёра.** Медиатека → Актёры → кнопка редактирования фото своей записи. Загрузите и сохраните. После обновления фото остаётся. На странице фильма оно также отображается. Для общего актёра кнопка доступна ADMIN.
9. **Форматы и лимиты.** Проверьте HEIC с телефона. Затем SVG, повреждённый файл, аватар больше 5 МиБ и постер больше 10 МиБ. Неверные файлы не сохраняются, ошибка понятная. Массовые запросы должны получать 429, интерфейс допускает повтор позже.
10. **Права.** Под другим обычным пользователем нельзя заменить общий или чужой постер/фото. Нельзя присвоить чужой `assetId` либо использовать свой аватар как постер. Сервер отклоняет запрос, даже если отправить его вручную.
11. **Отображение.** Проверьте узкий экран и десктоп, разные пропорции картинок. Постеры в списках имеют единый размер. Сохранённые миниатюры используются в сетках, большие изображения — в деталях. Обновление профиля не возвращает удалённые QA-фотографии.
12. **Коллекция.** Удаление фильма из личной коллекции не должно удалять общий постер. Другие пользователи продолжают видеть фильм в каталоге.
13. **Сетка профиля.** Переключите достижения «Открытые» и «Закрытые». Ширина страницы, боковые поля, высота соседней карточки друзей и положение аналитики должны оставаться одинаковыми. Длинный список достижений прокручивается внутри карточки, в том числе с клавиатуры. Проверить десктоп и телефон.

Проверяйте сценарии на десктопе и настоящих устройствах iOS/Android. Для проверки прав используйте отдельные тестовые аккаунты с ролями USER и ADMIN. После проверки удаляйте только созданные тестовые данные.

## Отдельная приёмка VPS

- Чистая база: вся история миграций применяется без `reset`/`db push`.
- Docker-образы собираются с публичным npm. Секретные файлы и локальные native-модули в них не попадают.
- HTTPS работает, вход и refresh сохраняют сессию после обновления.
- `/api/health` возвращает JSON `status: ok`, неизвестный API-маршрут не возвращает SPA вместо ошибки.
- PNG и HEIC проходят через nginx, возвращаются действующие HTTPS URL из S3 и доступны после перезапуска API.
- Чат работает в двух браузерах. При обновлении контейнер завершается с открытым соединением и новый backend проходит healthcheck.
- Бэкап уходит в отдельный приватный бакет. Восстановление проверено на отдельной базе. Бинарные изображения защищены отдельно от PostgreSQL.
- Проверены бюджет, лимит S3-трафика, автоапгрейд, память и свободное место.

Для локальной проверки контейнеров из корня проекта выполните `bash deploy/verify-local.sh`. Успех обозначается `FAVOURITE_DOCKER_CHECK_OK`. Скрипт использует отдельную пустую PostgreSQL и тестовый сертификат. Он не заменяет проверку реального S3, HTTPS на домене, чата и восстановления резервной копии. Настройки сервера описаны в [deploy/README.md](../deploy/README.md).
